# GeoMeasure K (kakaomap_coverage)

게이트웨이 커버리지(반경) 확인용 지도 측정 도구. 지점 좌표 확인·경로 거리 측정·지점별 반경원 표시·영역(방목지) 표시·GPS 실시간 추적 기능을 제공한다.

이름의 **K**는 원본 `GeoMeasure`의 **국내(카카오맵) 판**이라는 뜻이다. 지도 엔진 이름을 제품명에 넣지 않은 이유는 두 가지다 — 카카오 브랜드를 제3자 제품명에 쓰지 않기 위해서, 그리고 **나중에 지도 엔진을 바꿔도 이름이 거짓말이 되지 않게** 하기 위해서다.

> 카카오맵은 **대한민국 밖의 지도 데이터를 제공하지 않는다**(카카오 공식 답변: "카카오맵의 데이터 범위는 대한민국으로 한정됩니다"). 해외에서 서비스하려면 지도 엔진 교체가 필요하다. 저장 포맷을 GeoJSON으로 잡고 거리·면적 계산을 SDK에서 떼어놓은 것이 그 대비다 — 교체 시 바뀌는 것은 지도 레이어뿐이다.

## 원본 / 출처

이 도구는 [dream2k2/gmap-plus-fsm-](https://github.com/dream2k2/gmap-plus-fsm-) (`GeoMeasure`, Google Maps 기반)를 참조하여 새로 작성했다.

- 원본 배경: 국내 현장(제주 등)의 게이트웨이 커버리지 검토 시 Google 위성지도가 오래되어, 국내에서 더 최신인 **카카오맵 스카이뷰**로 지도 엔진을 교체했다.
- Google Maps API → **Kakao Maps JS API**로 전면 교체 (좌표계는 WGS84로 동일, 검색·오버레이 방식은 카카오 API에 맞춰 재작성).
- 지점 좌표/거리 계산 로직 등 지도 엔진과 무관한 부분은 원본의 구조를 참고했다.
- 이 저장소는 원본의 fork가 아닌 독립 저장소다.

## 기능

- 장소/좌표 검색 (검색 마커는 클릭으로 제거 — 지도 위치는 유지)
- GPS 현재 위치 확인 및 실시간 추적 (측위 정확도 ± 표시, 실패 시 사유·조치 안내)
  - 지도 위 **현재위치 표시는 끌 수 있다** — 오차가 크면 파란 오차원이 화면을 덮어 지점·반경원을 가린다. 꺼도 좌표·거리 계산은 그대로 돈다
- 지도 탭으로 지점 추가, 지점 간 경로 거리 자동 계산 (폐합 둘레 포함)
- 지점별 반경원(커버리지) 표시, 마커 드래그로 위치 조정
- **지점 순서 변경(▲▼)** — 지점은 항상 목록 끝에 붙는다. 빠뜨린 곳을 나중에 찍었으면 지우고 다시 찍지 말고 끌어올린다(지우면 붙여둔 사진까지 날아간다). 순서는 표시가 아니라 계산이다 — 구간 거리·총거리·폐합 둘레가 전부 이 순서로 나온다
- **지점 이름은 마커 아래에 같이 표시된다** — 산출물이 화면 캡처라 이름이 그림에 남아야 한다. 이름을 적은 지점만 표시되고(안 적으면 원 안의 A·B·C 뿐), 10자를 넘으면 줄여서 그린다
- **영역(폴리곤)** — 방목지·농장경계를 다각형으로 그리고 채움색·선색·투명도 지정, 면적 자동 계산
- **지도 위 텍스트** — 영역 이름·설명과 독립 텍스트, 라벨은 드래그로 위치 조정
- **지점 사진 첨부** — GW 설치 사진을 지점에 붙이고 파일 하나로 같이 오간다 (아래 "지점 사진")
- **GeoJSON 내보내기/불러오기** — 파일 하나 = 목장 하나, 드래그앤드롭 지원, 작업 자동저장
- **구글 드라이브에서 불러오기** — 공유 링크를 붙여넣거나, `?gd=` 주소 하나로 열자마자 불러온다 (아래 "드라이브에서 불러오기")
- 지도 타입 전환(스카이뷰 / 스카이뷰+라벨 / 일반 / 지형)

캡처 후 그림판으로 방목지 경계와 설명을 그려 넣던 수작업을 도구 안으로 옮긴 것이 영역·텍스트 기능이다.

### 저장 포맷

자체 JSON이 아니라 **GeoJSON**을 쓴다. 지도 엔진을 바꿔도 현장 데이터가 살아남아야 하기 때문이다.

| 항목 | geometry | properties |
|---|---|---|
| GW 커버리지 | Point | radius, label, color, name, **pid**, **photos** |
| 영역 | Polygon | name, desc, fillColor, strokeColor, opacity, labelPos |
| 텍스트 | Point | text, fontSize |
| 측정 경로 | LineString | — |

거리·면적처럼 **계산으로 나오는 값은 저장하지 않는다**(좌표를 옮겼을 때 어긋난 파일이 된다). 반경은 사용자가 정한 값이라 저장한다. 사진도 같다 — 계산이 아니라 사용자가 넣은 것이라 저장한다. 경로 LineString은 외부 뷰어용으로 내보내되, 불러올 때는 무시하고 GW 지점에서 다시 그린다.

- `pid` — 지점의 안정적 id. 사진을 브라우저 안에서 지점과 이어붙이는 열쇠다.
- `photos` — **배열**(`[{ "uri": "data:image/jpeg;base64,…", "name": "원본파일명.jpg" }, …]`). 설치 사진은 전경/근접/명판 식으로 여러 장이 되므로 처음부터 배열로 둔다. 단수로 뒀다가 나중에 바꾸면 이미 나간 파일과 호환이 깨진다.
  - `name` = **원본 파일명**. 현장에서 파일명 자체에 정보를 담아 찍는다(예: `색달목장_방목지_언덕2_D4F98D066F1D_260713.jpg` — 목장·구역·지점·MAC·날짜). 리사이즈하면 EXIF가 통째로 날아가므로 **파일명이 남는 유일한 촬영 맥락**이다. 이름이 없으면 키 자체가 빠진다.
  - 항목이 문자열(`"data:image/jpeg;base64,…"`)인 초기 형식도 그대로 읽는다(그때는 이름이 빈 값). 파일명을 별도 배열로 두지 않은 이유는 사진을 지울 때 인덱스를 두 군데 맞춰야 하기 때문이다.

**역호환**: `photos`·`pid`가 없는 기존 파일도 그대로 열린다. 반대로 사진을 모르는 구버전·외부 뷰어가 새 파일을 열어도 `properties`는 GeoJSON 자유 필드라 무시될 뿐이고 좌표·반경·영역은 그대로 산다.

불러오기는 신뢰 경계로 취급한다. 좌표 범위·타입·필수 필드를 검증하고, 버린 항목은 사유를 화면에 남긴다. 사진은 여기에 더해 `data:image/(jpeg|png|webp);base64,` 접두어·한 장 2MB·지점당 20장으로 제한한다(외부 파일의 문자열이 `<img src>`로 DOM에 들어가는 유일한 경로다).

### 지점 사진

이 도구는 "설치 **전** 위치 계산"인데 사진은 "설치 **후** 기록"이라 두 시점이 갈린다. 그래서 **기존 GeoJSON 불러오기 → 지점 선택해 사진 첨부 → 내보내기**의 왕복이 핵심이고, 파일 하나로 오간다(zip을 쓰지 않는 이유이기도 하다 — 브라우저에 zip 생성 표준이 없고, JPEG는 이미 압축돼 있어 줄지도 않는다).

- 첨부: 패널 지점 목록의 📷 또는 지도에서 마커 클릭 → 팝업의 **📷 사진 추가** (여러 장 동시 선택 가능)
  - 폰에서는 OS 선택창이 **촬영 / 앨범 / 파일**을 모두 제시한다. `capture="environment"`를 쓰면 카메라가 한 번에 열리지만 UA에 따라 앨범 선택지가 사라져서 채택하지 않았다.
- 사진이 있는 지점은 지도 마커에 **카메라 배지**가 붙는다
- 저장 위치가 둘로 갈린다 — 목적이 다르기 때문이다

| | 어디에 | 형식 | 왜 |
|---|---|---|---|
| 자동저장 | IndexedDB | Blob 그대로 | localStorage는 origin당 약 5MB 고정이고 구글맵 판과 나눠 쓴다. 사진을 넣으면 몇 장 만에 자동저장이 통째로 죽어 **좌표까지 유실**된다 |
| 내보내기 | GeoJSON 파일 | base64 data URI | 파일 하나로 오가야 하므로 |

- 원본을 넣지 않는다: **최장변 1280px · JPEG 품질 0.75**로 리사이즈한다(약 250KB). 목적이 설치 상태 기록이라 이걸로 충분하다.
- 리사이즈는 canvas 재인코딩이라 **EXIF가 통째로 제거된다** — 촬영 GPS·기기정보가 내보낸 파일에 실리지 않는다(의도한 이득). 대신 회전정보도 같이 사라지므로 `createImageBitmap(file,{imageOrientation:'from-image'})`으로 먼저 회전을 적용한다. 이게 빠지면 세로로 찍은 폰 사진이 90도 눕는다.
- EXIF가 사라지는 대신 **원본 파일명을 보존한다**. 썸네일에 마우스를 올리면(title), 확대 보기에서는 사진 아래에 글자로 보인다.
- 지점을 지우면 그 지점의 사진도 IndexedDB에서 같이 지운다. 주인 없는 사진은 다음 실행 때 정리된다.

### 드라이브에서 불러오기

목장 파일을 드라이브에 두고 **링크 하나로 현장 폰에 띄우는** 용도다. 다운로드 → 파일선택 두 단계를 없앤 것이고, 기존 불러오기와 하류가 같아 검증·자동저장 동작도 같다.

- 저장/불러오기 카드의 입력창에 **드라이브 공유 링크를 붙여넣고 `☁ 가져오기`**
  - 받는 형태: `/file/d/<ID>/view` · `/open?id=<ID>` · `uc?export=download&id=<ID>` · 파일 ID 단독
- 링크가 유효하면 아래에 **`?gd=<파일ID>` 주소와 복사 버튼**이 뜬다. 그 주소를 열면 지도가 바로 그려진다.
  - 주소는 `location`에서 만든다 — 라이브에서 만들면 라이브 주소, `-dev`에서 만들면 dev 주소가 나온다.
  - 링크 통째가 아니라 **파일 ID**를 싣는다. 링크를 넣으면 URL 안에 URL이 들어가 인코딩으로 두 배 넘게 길어지는데, ID 단독도 받으므로 잃는 게 없다.
- 파일 공유는 **"링크가 있는 모든 사용자" + 역할 "뷰어"**. 다운로드만 하므로 편집자 권한은 필요 없다.

**왜 로그인이 없나** — 공유 링크를 그대로 `fetch`하면 CORS로 막혀(응답에 `Access-Control-Allow-Origin`이 없다) Drive API를 쓴다. 여기에 OAuth를 붙이면 비공개 파일도 열리지만, **링크를 받는 사람마다** 구글 로그인 + 테스트 사용자 사전등록 + "확인되지 않은 앱" 경고를 거쳐야 해서 "링크 하나로 열린다"는 목적과 정면으로 어긋난다. 그래서 API 키(익명 요청)를 쓰고, 공개 공유를 전제로 둔다. 비공개 자료를 다뤄야 할 일이 생기면 그때 OAuth를 꺼낸다.

링크에서 **파일 ID만 떼어** 쓰므로 요청처가 `googleapis.com` 하나로 고정된다. 링크는 URL 파라미터로도 들어오는(= 남이 정하는) 값이라 임의 URL을 그대로 `fetch`하지 않는 것이 신뢰 경계다.

`?gd=`로 열 때 복원된 작업이 있으면 확인을 받는다. 실제 초기화는 응답을 파싱해 **읽을 항목이 있음을 확인한 뒤에만** 일어나므로, 응답이 GeoJSON이 아니어도 화면의 작업은 그대로 남는다.

| 증상 | 원인 |
|---|---|
| `404` | 링크 오타이거나 공유가 "링크가 있는 모든 사용자"가 아님 — 구글이 비공개 파일에도 404를 주므로(존재 은닉) 코드로 못 가른다 |
| `403` | API 키 리퍼러 제한·할당량·Drive API 사용 설정 |

## 사용 / 설정

정적 HTML 한 파일이라 별도 빌드가 필요 없다. 웹서버에 `index.html`을 올리면 동작한다.

단, **Kakao Maps JavaScript 키**가 필요하다. [Kakao Developers](https://developers.kakao.com)에서 애플리케이션을 만든 뒤 아래 3가지를 설정한다. **하나라도 빠지면 지도가 안 뜬다.**

### 1. JavaScript 키를 코드에 넣기

`내 애플리케이션 > 앱 설정 > 앱 > 플랫폼키`

여기의 **JavaScript 키**를 `index.html` 맨 아래 SDK 로드 URL의 `appkey=`에 지정한다.

```html
<script src="https://dapi.kakao.com/v2/maps/sdk.js?appkey=여기에_JavaScript_키&libraries=services&autoload=false"></script>
```

### 2. 도메인 등록 (JavaScript SDK 도메인)

`내 애플리케이션 > 앱 설정 > 앱 > 플랫폼키 > JavaScript 키 [수정] > JavaScript SDK 도메인`

> ⚠️ 도메인 등록란은 **JavaScript 키 항목의 `수정` 안**에 있다. 별도의 "플랫폼" 메뉴가 아니다 — 여기서 많이 헤맨다.

서비스할 주소를 **origin(스킴 + 호스트 + 포트)** 형태로 등록한다.

| 용도 | 등록값 |
|---|---|
| 운영 | `https://yepark.co.kr` |
| 로컬 확인 | `http://localhost:8080` |

- **경로(`/bovicare-gmapkakao`)는 검사하지 않는다.** origin만 맞으면 된다 — 경로까지 넣으면 오히려 안 된다.
- 미등록 시 SDK 요청이 `401 domain mismatched`로 거부된다.

### 3. 카카오맵 제품 활성화

`내 애플리케이션 > 제품 설정 > 카카오맵` → **ON**

- 키와 도메인이 다 맞아도 이게 꺼져 있으면 `403 disabled OPEN_MAP_AND_LOCAL service`로 거부된다.
- 앱을 새로 만들면 **기본값이 OFF**다. 새 앱으로 옮길 때 반드시 다시 켠다.

### 4. 구글 드라이브 가져오기 (선택)

이걸 안 해도 나머지 기능은 다 돈다 — 드라이브 버튼만 "설정되지 않았습니다" 안내를 낸다.

1. **[Drive API 사용 설정](https://console.cloud.google.com/apis/library/drive.googleapis.com)** → `[사용]`
2. **[사용자 인증 정보](https://console.cloud.google.com/apis/credentials)** → `[+ 만들기] > API 키`
3. 만든 키 → `[키 수정]`
   - 애플리케이션 제한: **HTTP 리퍼러** → `https://yepark.co.kr/*`
   - API 제한: **Google Drive API**
4. `index.html`의 `GDRIVE_KEY`에 넣는다

- **API 제한 드롭다운은 "사용 설정된" API만 보여준다.** 1번을 먼저 하지 않으면 목록에 `Google Drive API`가 안 나온다(`Google Cloud APIs`는 별개 항목이라 Drive를 포함하지 않는다).
- 현재는 `webpage-googlemap-coverage`의 Maps 키와 **같은 키**를 쓴다(같은 프로젝트에 Drive 추가). 같은 origin의 다른 페이지에 이미 공개돼 있어 여기 넣는다고 노출이 늘지 않는다. 다만 그 키 하나로 **과금 API인 Maps**도 부를 수 있으니 [예산 알림](https://console.cloud.google.com/billing/budgets)을 걸어두는 편이 낫다. 분리하려면 새 키를 만들어 `GDRIVE_KEY` 한 줄만 바꾸면 된다.

키가 실제로 통하는지는 브라우저 없이 확인할 수 있다. 리퍼러 제한은 헤더 기반이라 서버에서도 재현된다.

```bash
curl -s -H "Referer: https://yepark.co.kr/bovicare-gmapkakao/" \
  "https://www.googleapis.com/drive/v3/files/<가짜ID>?alt=media&key=<KEY>" | head -5
# 404 File not found  → 키·API 사용설정·리퍼러 전부 정상 (파일 ID만 가짜)
# 403 API_KEY_HTTP_REFERRER_BLOCKED → 리퍼러 제한에 도메인이 없다
```

---

> 카카오 JavaScript 키는 클라이언트에 노출되는 것이 정상이며, **도메인 화이트리스트로 보호**된다. 그래서 이 저장소에는 키를 코드에 그대로 둔다. 구글 API 키도 같은 성격이다 — 다만 리퍼러 제한은 헤더 기반이라 위조되므로, **공개 파일만 읽는 용도**라는 전제가 같이 간다.

지도가 안 뜨면 화면에 **현재 접속 origin**과 함께 안내가 표시된다. 그 값을 위 2번에 그대로 복사해 넣으면 된다. 브라우저 콘솔의 에러 코드로 원인을 가릴 수 있다:

| 증상 | 원인 | 조치 |
|---|---|---|
| `401 domain mismatched` | 도메인 미등록 | 2번 |
| `403 disabled OPEN_MAP_AND_LOCAL service` | 카카오맵 제품 OFF | 3번 |

## 자체 점검

지도 SDK 없이 순수 로직만 확인한다. 도메인 등록 전에도, 브라우저 없이도 돌아간다.

**브라우저에서 거리만 빠르게 보기**

```
index.html?selfcheck=1
```

**전체 검증 (거리 · 면적 · GeoJSON 파싱 · 입력 검증)**

```
node selfcheck.test.js
```

의존성·프레임워크 없이 `node`만 있으면 된다. `index.html`의 인라인 스크립트를 **매번 그대로 추출해** 돌리므로 사본이 갈라지지 않는다.

기준값은 원본 도구로 측정한 용춘목장 3지점(A↔B 196.7 m · B↔C 237.9 m · C↔A 355.5 m)이다. **거리 계산부를 수정했다면 반드시 통과를 확인할 것.** GeoJSON 불러오기는 신뢰 경계라 손상·악의적 입력(위경도 뒤바뀜, NaN, CSS 주입, 과대 반경, 초장문 문자열)도 함께 검증한다.
